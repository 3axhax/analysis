# Предложение: градации коэффициента де Ритиса

Методичка, стр. 35, содержит семь строк. Это не семь непересекающихся диапазонов: строки `≥2`, `≥1,7`, `1,5`, референс `0,91–1,75`, `1`, `<1`, `<1,5` перекрываются. Референс — граница статуса, а не отдельная причина. Показатель рассчитывается как АСТ/АЛТ только при совместимых единицах и положительном АЛТ. Утверждения источника требуется показывать как возможности, не устанавливая диагноз или наличие симптомов/приёма препаратов.

Предлагается оставить статус LOW/NORMAL/HIGH по референсу 0,91–1,75, а числовые строки интерпретации проверять независимо от статуса. Зафиксировать сравнения в отдельном модуле и связать каждое с отдельным редактируемым описанием по стабильному смысловому ключу, а не ID последовательности БД. Показывать только выполнившиеся условия. Это позволит в ячейке параметра показывать и статус, и конкретное условие, а тексту не повторять эти сведения.

| Строка методички | Условие |
| --- | --- |
| 1 | `КР ≥ 2` |
| 2 | `КР ≥ 1,7` |
| 3 | `КР = 1,5` |
| 4 | `0,91 ≤ КР ≤ 1,75` — только статус NORMAL, не дополнительное описание |
| 5 | `КР = 1` |
| 6 | `КР < 1` |
| 7 | `КР < 1,5` |

Предлагаемое разрешение пересечений: показывать каждое применимое описание, не считать строки взаимоисключающими. Например, при 1,72 статус NORMAL и срабатывает `≥1,7`; при 2 срабатывают и `≥1,7`, и `≥2`; при 1 срабатывают `=1` и `<1,5`. Точное `1,5` не входит в `<1,5`. Это обеспечивает буквальную логику операторов источника и явно показывает совпадающие правила; при желании уменьшить число описаний следует отдельно согласовать приоритет, потому что источник его не устанавливает.

Проверки сравнивают точные десятичные исходные значения через `AST` и `ALT × порог`, а не округлённое число на экране. Для двусторонних и равных операторов зафиксировать включительность. Тестировать значения чуть ниже, ровно и чуть выше 0,91, 1, 1,5, 1,7, 1,75, 2, оба пола и возраста, AST=0, ALT=0, отсутствие/дубли/разные единицы и границы при периодической дроби; статусы и градации должны использовать один исходный расчёт. При отсутствии допустимой пары не выдавать никакое правило. Учитывать общий и источниковый контексты, не создавать виртуальное сохранённое измерение и не выдавать результаты разных источников за подтверждение друг друга.

Это предложение, а не внедрённое изменение. Сейчас работает только референсный статус и описание по LOW/HIGH; отдельного правила `≥2` нет. Перед реализацией нужно согласовать поведение при перекрытиях, затем подготовить миграцию текстов и связей, интерфейс просмотра условий в админке, synthetic tests и обычный HTTP save/get. Переносить из методички рекомендации о дозах/диагнозах как установленные факты нельзя; сравнить условные формулировки с источником и клиническим контекстом.
