# Реализация

## Поведение
Иерархия `medicalSource` использует `parent_id`, название и JSONB metadata. Для источников документов нормировки и описания связаны `sourceId`; прежние данные имеют NULL. `sourceReferenceInheritance` связывает документ и показатель с текущим общим нормативом. Приоритет имеют собственные данные источника в контексте age/gender; наследование применяется лишь в отсутствии собственных данных и при наличии явной связи. Источник с односторонним нормативом возвращает LOW ниже минимума либо HIGH выше максимума; граница включена в NORMAL, отсутствие второй границы не заполняется фиктивным числом. Пересчёт выполняется в существующем нормализаторе единиц. Условия описаний сопоставляются исключительно в рамках соответствующего источника.

GET результата сохраняет прежние `result` и `descriptions`, добавляет `sourceDescriptions` с информацией о корне и наследовании. Клиент отображает выводы и позволяет отключать корневые группы и общий набор. Выводы по источникам и набор источников не заполнялись: содержание и права документов требуют подготовки отдельной миграцией/набором данных. Админка пока не разделяет общие и источниковые нормативы; до задачи 0011 нельзя безопасно редактировать показатель в админке при наличии данных источников.

## Схема и миграции
Startup migrations `0010-medical-sources`, `0011-medical-source-parent-id` используют общую транзакцию и advisory lock `runRecordedMigration`, не меняют старые строки. Второй шаг переименовывает поле в согласованное `parent_id`; исходный шаг устойчив к уже созданным пустым таблицам Sequelize. Новые модели регистрируются после миграций, поэтому на свежих установках таблицы создаются миграцией, а не автоматической синхронизацией. Циклы запрещены, перемещение существующих узлов пока запрещено; управление иерархией относится к задаче 0011. Удаление связанных источников ограничено FK. Старые entity CRUD до задачи 0011 не адаптированы.

Автоматического отката нет: перед удалением схемы необходим отдельный согласованный план с учётом записей и работающей версии; откат маркера при работающем backend вызовет повторный запуск миграции. Прямые SQL-файлы из каталога задачи не запускать, схема поставляется через встроенные миграции.

## Проверки
Миграция проверена на синтетической схеме внутри транзакции с rollback; обе отметки присутствуют в локальной БД. Справочные counts min/max/description до и после: 1898/1898/133. Создано три синтетических результата для обычной проверки save/get после этапов изменения startup и миграций, capability-ссылки не выводились. Полный backend: 23 набора, 201 тест; backend build, client build и client lint прошли. Сборка клиента выводит ранее существовавшие предупреждения оптимизатора CSS и размера чанка. Проверка API с реально загруженными источниками и визуальная проверка фильтра с данными остаются на этап наполнения источников: таблица источников пуста.

Локальный дамп не создавался по прямому указанию пользователя. Автоматический reviewer ранее отклонил создание полного дампа; при повторном обслуживании учитывать риски восстановления и отдельные требования пользователя.

## Загрузка первого источника — 2026-11-06
Миграция `0012-soppi-iron-source` добавляет PMC и публикацию Soppi 2018 с CC BY 4.0, одно адаптированное описание, два минимума ферритина 30 мкг/л для существующей взрослой возрастной группы и обоих полов, а также явное наследование общих границ гемоглобина. Идентификаторы показателей и единиц ищутся по именам и кодам; совместимость справочника проверяется до вставки. Дети исключены консервативно для пилота. Повторный вызов журналированной миграции не дублирует данные. Пять новых синтетических результатов сохранены для проверок, capability ID не фиксировались; результаты без медицинских данных реальных людей. Авторство и ссылка на лицензию отображаются пользователю. Админские ограничения и отсутствие медицинской проверки сохраняются.

## Второй источник — 2026-11-06
Миграция `0013-nutritional-iron-source` добавляет корневой источник Principles of Nutritional Assessment и главу Iron (Gibson RS, Friel JK, 2024, CC BY 4.0), два порога ферритина <15 мкг/л для взрослого возрастного интервала и обоих полов, наследование общих нормативов гемоглобина, одно описание и два условия. Описание сообщает о возможности дефицита железа с анемией, не объявляя диагноз. Источник указывает происхождение используемых положений от Lynch et al. (2018); карточка выводит ссылку на первичную публикацию. Ограничение взрослой группой введено для пилота. Миграция проверяет наличие справочных элементов и корректность общих нормативов, выполняется атомарно и не переписывает общие записи.

Синтетическая схема с rollback, повторный запуск миграции и HTTP endpoint на шести синтетических результатах прошли. Общие records min/max/descriptions: 1898/1898/133. Backend build и 17 профильных тестов, client build/lint и 4 теста карточки источника прошли. Шесть синтетических результатов сохранены локально; ID и ссылки не фиксировались. Медицинской проверки специалистом нет; админка остаётся отложенной задачей 0011.
# Уточнение источников железа, 2026-11-06

Миграция 0014 заменяет наследование норматива гемоглобина для Soppi и Gibson/Friel собственными порогами статей и добавляет два трёхпараметрических описания для железа, трансферрина и ОЖСС. Для этих трёх показателей границы наследуются из сервиса; об этом сказано в тексте интерпретации. Порог Gibson/Friel у женщин относится к небеременным; оговорка видна в описании, поскольку признак беременности не собирается. Порог исторический, для уровня моря.

В нижний норматив добавлен `lowInclusive`: для Soppi гемоглобин на пороге считается LOW, для остальных нормативов поведение не изменилось. Проверены перевод единиц и значения ниже, на и выше границы; SQL сначала исполнен в транзакции с откатом, затем автоматически применён с marker миграции. Backend build и 15 профильных тестов прошли; четыре синтетических HTTP save/get проверили срабатывание на мужских и женских порогах. Клиническая проверка специалистом отсутствует.
