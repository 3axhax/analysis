# Механизм интервалов

## Цель и поведение

Заменить раздельные границы независимыми интервалами показателя с контекстом источника, возраста, пола и единицы. Интервал допускает отсутствующую границу, включительные и исключительные концы, пересечение и необязательный статус. Описание срабатывает, когда выполнены все его условия; условие выполняется при совпадении любого связанного с ним интервала. Один интервал может использоваться несколькими условиями, включая условия описаний других источников. Фильтр источников управляет показом описаний, а не проверкой их интервалов.

## Текущее состояние

`server/src/unitConversion/unit-conversion.service.ts` читает отдельные таблицы минимумов и максимумов; `server/src/analysisResult/analysisResult.service.ts` и `server/src/analysisResultDescription/analysisResultDescription.service.ts` подбирают описания по статусам. Ряд описаний использует специальные правила расчётных показателей. Админка и миграции также зависят от прежней структуры. Сохранённые результаты не являются эталоном совместимости по указанию пользователя.

3. Подготовить атомарную миграцию, ограничения и перенос однозначных пар; отдельно отразить отсутствующие или неоднозначные границы. Сохранить возможность проверки на отдельной копии. Удаление прежних таблиц и применение миграции требуют отдельного подтверждения согласно AGENTS.md.

## Подготовленный переход

Создан отдельный выключенный по умолчанию переключатель `INTERVAL_MODEL_ENABLED`. При включении чтение результата использует интервалы, а прежние операции записи нормативов и описаний блокируются, чтобы не расходились две модели. Интервальный административный API защищён ролью ADMIN и выключен вместе с переключателем. Существующий интерфейс админки ещё не переведён; из-за этого режим нельзя считать готовым к включению.

Подготовленная миграция 0055 атомарно создаёт новые таблицы, переносит однозначные полные пары и соответствующие условия, а специальные численные правила переносит в самостоятельные интервалы. 17.11 пользователь отдельно согласовал перенос 16 уже проверенных односторонних порогов двух источников: LOW сохраняет включительность, единственное условие «гемоглобин выше порога» получает отдельный интервал со статусом null. Другие односторонние случаи не додумываются. Финальная миграция 0056 проверяет наличие связей условий и перенесённых границ перед удалением старых таблиц и полей, но не заменяет медицинскую проверку. Миграции зарегистрированы для запуска только при `INTERVAL_MODEL_ENABLED=true`; переключатель сейчас выключен, к рабочей БД миграции не применялись. Перед включением нужно показать окончательный план, обновить и проверить backup и получить явное подтверждение согласно корневому AGENTS.md. В новом режиме отключено автоматическое `sequelize.sync`, чтобы старые модели не воссоздали удалённые таблицы.

SQL проверен на изолированной тестовой БД с синтетическими данными: операторы на границах, односторонние случаи, дубликаты, отказ 0056 при неперенесённых данных, повторное применение и атомарность. Далее отдельно согласовать проверку на копии локальной БД и сверить агрегаты, не раскрывая содержимое. При откате не терять новые интервалы и связи: автоматическое удаление новых таблиц с пользовательскими изменениями запрещено; восстановление backup и остановка новой версии выполняются только по отдельному согласованию.

Проверка изолированной копии согласована пользователем и выполнена: 13 610 интервалов, условий без связей нет; агрегаты основных данных до и после не изменились, транзакционный откат и повторный запуск прошли. Новый HTTP save/get и расчётные показатели проверены синтетическими измерениями на копии; anonymous, USER, ADMIN, неверный и отозванный токены проверены синтетическими сессиями без их вывода.

Предлагаемое локальное включение после отдельного согласия: скрипт `server/scripts/enable-interval-dev.sh` создаёт свежую проверяемую копию БД вне задач и повторяет read-only preflight; добавляет переключатель в локальную конфигурацию, пересоздаёт только dev backend и запускает при его старте миграции 0055/0056; проверяет отсутствие старых таблиц, покрытие условий, неизменность агрегатов и HTTP save/get на синтетическом результате. В новом режиме старый редактор нормативов и описаний временно недоступен, пока не выполнена отдельная задача в TODO; административный API интервалов защищён ADMIN. При ошибке автоматический откат или восстановление не выполняются: нужно остановиться, установить состояние и отдельно согласовать восстановление. Production не затрагивается.

## Риски и проверка

Медицинские границы нельзя додумывать. Переносить лишь однозначные данные, сохраняя операторы существующего поведения; источники с неопределёнными дробными промежутками отдельно проверять. Не выводить индивидуальные данные и capability-ссылки. Миграция обязана быть атомарной и иметь проверенный план отката; не удалять provenance и данные измерений. Применение к локальной БД и перезапуск backend с pending migrations — только после плана и отдельного подтверждения пользователя.
