## Итог на 2026-10-15, 18:26 UTC+05:00

Реализованы DB-backed aliases единиц (`code`, `translationParsing`, `quantityKind`), версия прямого преобразования и decimal resolver. Сначала выбирается полный норматив в исходной unit для point/age/gender. Иначе допускается прямая активная конверсия в разрешённую unit с нормативом. Эквивалентные интервалы выбираются детерминированно; противоречивые, неполные, дублированные или перевёрнутые интервалы не дают NORMAL. Нормативы не объединяются, фиксированной расчётной unit у показателя нет.

Парсер сохраняет исходное значение и явную unit непосредственно после него. Глобальные коллизии aliases не угадываются по point. Admin редактирует варианты через `_`; валидация отвергает пустые, повторные и конфликтующие варианты. Runtime также отказывает при коллизии, включая возникшую вне admin API. Проверка aliases не заменена отдельным DB UNIQUE для каждого элемента строки.

Save повторно проверяет point/unit, возраст/пол и значения; в repeatable-read транзакции нормализует весь набор до создания результата и атомарно сохраняет родителя/точки. Ноль разрешён; отрицательное/нечисловое, неизвестные или запрещённые единицы и дубли point отвергаются. Клиентский коэффициент игнорируется. Сохраняются sourceValue/sourceUnitId/sourceUnitText, calculationValue и снимок rule/version/coefficient/reference bounds. Decimal calculationValue авторитетно, старые value/unitId остаются совместимым расчётным представлением.

GET возвращает исходные value/unit и обратнопереведённые отображаемые границы; `calculation` содержит расчётные decimal-строки и provenance. Новые результаты читаются по снимку, не по текущей версии коэффициента. Старые строки не переписываются, проверяются по текущим нормативам. При отсутствии однозначного норматива status/bounds=null с предупреждением; описания используют тот же статус. Ошибки хранения не раскрывают SQL/payload.

UI сохраняет распознанную единицу, не выбирает первую при отсутствии evidence, не умножает значение при ручной смене unit, не обрезает дробную часть и показывает исходное обозначение. Отсутствующая интерпретация не отображается как норма.

Миграция применена к локальной БД после проверки up/repeat/down на отдельной копии. Добавлены g/dl и две разрешённые связи (гемоглобин/MCHC); всего 8 прямых правил. Down-скрипт отказывает при наличии новых нормализованных результатов, чтобы не уничтожить provenance. После появления таких результатов не удалять новые столбцы/правила; согласовывать отдельный data-preserving rollback. Массового backfill нет.

Ограничения: только прямые положительные линейные коэффициенты, без цепочек, offsets, mass↔molar или percent↔count. Глобальное правило не разрешает исходную unit всем point автоматически. ## Реализовано без изменения БД

-reference-normalization.ts: независимый resolver нормативов для точного point/age/gender. Exact source unit приоритетна; иначе только прямые активные утверждённые rules, с point applicability. Разные доступные единицы сами по себе не блокируют point. Эквивалентные intervals сравниваются cross-products без округления inverse границ; конфликт даёт conflicting_reference_ranges. Неполные/дублированные/reversed ranges не становятся NORMAL, invalid exact interval не скрывается конверсией в другой unit.
-Decimal.js10.4.3 установлен из локального npm-cache, pinned dependency; иных версий пакетов не меняли. Precision80 покрывает exact products двух38-digit чисел; input/coeff finite,<=18 decimal places иabs<1e20. Только отображаемые inverse limits округляются до20dp; сравнения используют неокруглённое произведение. Ноль допускается, negative/NaN/overflow отвергаются. Snapshot result содержит source/calculation/rule/version/coefficient/reference bounds/status.
-unit-alias-index.ts: translationParsing через `_`, name/code, безопасная Unicode/space нормализация с сохранением регистра. Различает m/M, g/l иg/dl; глобально конфликтующий alias не угадывается по единственной разрешённой unit. Diagnostic issues для пустых/повторных/конфликтующих вариантов. Пока не подключён к runtime DB loader: старый schema не имеет translationParsing/code.
-Client PDF reducer больше не выбрасывает подтверждённую unit из findings; value не умножается. Ручной ввод/сохранение/результат пока используют прежний API, новое полное исходное представление ещё не подключено.
-Подготовлены manual up/down SQL в server/scripts/migrations/0002-unit-normalization*.sql, не auto-start. Никакой calculationUnitId у point. Scope:3 columns для15 units,+g/dl,+2 links,+conversion table8 rules,+9 provenance/decimal columns и migration marker. SQL ещё не исполнялся, тесты миграции не заявляются успешными.
