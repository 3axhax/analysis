# Возможные интерпретации в статьях показателей

Клиент загружает блок после открытия статьи через публичный GET /analysisPoint/:pointId/interpretations. Сервис подбирает записи по условиям текущего показателя, возвращает опубликованные источники и сортирует строки по числу уникальных показателей и ID.

Внутри группы с одинаковым текстом, источником и набором показателей сервис сравнивает наборы ID интервалов. Если число уникальных комбинаций равно произведению числа вариантов по показателям, таблица показывает одну строку с альтернативными статусами через «или». Описания из разных источников выводятся отдельными строками.

В таблице показатель статьи стоит первым, остальные сохраняют порядок и ссылаются на свои статьи при наличии публичного адреса. Используются те же кнопки и подсказки источников, что в расшифровке. При пустой выборке секция скрыта. Статический HTML статьи дополняется таблицей после загрузки данных.

Изменений схемы, данных, конфигурации и расчёта расшифровки нет. Для отката достаточно отменить коммит приложения.

Проверены отсутствие повторяющихся ID и порядок строк в публичном API, подсказки и ссылки на статье ферритина, объединение восьми сочетаний и первый параметр во всех 21 строках статьи гемоглобина. Для пролактина локальная выборка пуста. Прошли тесты клиента, тесты агрегации и чтения результата.

Сборки сервера и клиента прошли, включая пререндеринг 119 публичных страниц на Node.js 22. Проверка /health, lint клиента, 43 теста клиента и 8 профильных тестов сервера прошли.
