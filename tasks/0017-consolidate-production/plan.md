# Единая структура рабочего сервера

Цель — использовать `/var/analysis/analysis` как единый каталог сервиса и избавиться от отдельных checkout/release/override в `/var/analysis`. Данные PostgreSQL, существующие env, сертификаты, настройки Nginx, uploads, действующие образы и резервные материалы сохранить. Новые дампы не создавать по ранее выраженному указанию.

Исходное состояние: checkout `analysis` на старом main, содержит локальные конфигурации; live nginx использует файлы внутри него. Новый checkout `checkout-33e7221` управляет backend/client через отдельный override; backend монтирует uploads из старого release, PDF связан с release manifest. Старый `git pull --ff-only` отказался из-за `nginx/default.conf`; пробное трёхстороннее объединение чистое и даёт байтово неизменный рабочий конфиг.

План: подготовить в едином каталоге актуальный Git checkout и Compose-конфигурацию с текущими env, сертификатами и uploads без перезаписи исходных пользовательских конфигураций; проверить фактические значения и mount paths без раскрытия секретов. Вносить только необходимые переключения контейнеров, не пересоздавать PostgreSQL. Проверить содержимое uploads и состояние БД до/после, публичные endpoints, исходный и новый image/commit, состав контейнеров и сохранность настроек. Удалять только неиспользуемые каталоги исходников по запросу пользователя после проверки ссылок; резервные материалы и данные сохранить. Запуск backend потенциально применяет миграции; предварительно проверить markers. Документировать фактические пути и порядок последующей поставки.
