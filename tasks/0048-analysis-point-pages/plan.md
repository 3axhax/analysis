# Правки страниц показателей анализов

## Цель и границы

Подготовить изменения публичных страниц показателей по адресу `/pokazateli/<urlAlias>/`. Перечень правок, ожидаемое поведение и критерии приёмки предстоит уточнить.

## Текущее поведение

[Страница показателя](../../client/src/pages/articles/AnalysisPointArticlePage.tsx) выводит название, русское описание при наличии и ссылки на разделы, в которые входит показатель. Данные поступают из публичного каталога БД через `GET /analysisType?view=articles`. Публичный HTML, canonical и sitemap формируются из каталога при сборке. Текущий сценарий для проверки доступен на `/pokazateli/hemoglobin/`.

## Этапы и проверка

1. Зафиксировать требования и определить затронутые компоненты, данные и метаданные.
2. Реализовать согласованные правки. Определить необходимость миграции и порядок отката после уточнения требований.
3. Проверить клиентские сборку и lint, прямое открытие страницы, переходы со страниц разделов и главной. В зависимости от изменений проверить отсутствующее описание, неизвестный алиас и сгенерированный HTML.

## Первый этап — описания показателей

Сверить текущие тексты и список показателей с методичкой `tmp/metoda45_c.pdf` и ранее разобранными публикациями, которые связаны с референсами или интерпретациями показателя. Для каждой записи зафиксировать проверенные источники и места в источниках, отсутствие материала и неоднозначности. Связи с референсами и интерпретациями использовать для поиска публикаций, где может быть объяснение показателя. На этом этапе диапазоны и пороги не сверять и не переносить в текст.

- `pointHintRu` и `pointHintEn` — короткая справка простым текстом для карточек и подсказок.
- `pointDescriptionRu` и `pointDescriptionEn` — развёрнутое описание для отдельной страницы. Английскую версию готовить по согласованному русскому смыслу, сверяя терминологию с источником.
- Для развёрнутого описания предложить ограниченную HTML-разметку с очисткой перед отображением. Иллюстрации рассматривать при подтверждённых правах на конкретный рисунок, с указанием источника и альтернативным текстом.
- Начать с ОАК для проверки редакционного формата, затем пройти остальные разделы. Готовить таблицу изменений по показателям для проверки перед миграцией. Новых столбцов для текстов не требуется.

## Содержание и ссылки

Пользователь подтвердил разрешение дословно публиковать и переводить фрагменты методички. Сохранять её формулировки там, где они подходят для справочного текста, и фиксировать страницы в рабочей сверке.

В развёрнутом описании объяснять, что измеряется, какой процесс отражает показатель и какие механизмы с ним связаны. Дополнительный контекст включать, если он раскрывает сущность показателя и прямо подтверждён источником. Референсные интервалы, пороги и сценарии интерпретации результатов в описание не включать.

В развёрнутом описании ставить ссылки на внешние источники рядом с утверждениями, которые они подтверждают. Подсказки оставить простым текстом. Блок интерпретаций готовится отдельно.

## Остальные показатели

Распространить формат ОАК на остальные показатели каталога. Поиск и отбор текста описаны в [инструкции](source-workflow.md). Обновить четыре поля по устойчивым ключам отдельной миграцией. Проверить точный охват каталога, сохранность текстов ОАК и остальных полей за пределами миграции, затем сверить выдачу через API.

## Продолжение расширенного формата

После пролактина переработать остальные 99 описаний на русском и английском. Добавить содержательные блоки о механизме или измерении, использовать списки для уместных сравнений и оставить источники в конце. Обновить только два поля развёрнутого описания одной транзакционной миграцией. Пользователь разрешил локальное применение после проверки.
