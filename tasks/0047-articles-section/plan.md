# Правки раздела статей

## Цель и границы

Подготовить изменения публичного раздела «Статьи» (`/articles`). Желаемое поведение, перечень правок и критерии приёмки будут уточнены по требованиям пользователя. На этапе подготовки создаются документы задачи.

## Текущее поведение

[Страница статей](../../client/src/pages/articles/ArticlesPage.tsx) показывает заголовок, вводный текст и карточки со ссылками на страницы групп анализов. Карточки формируются из [каталога групп](../../client/src/shared/config/analysis-groups.json). Маршрут зарегистрирован в [AppContainer](../../client/src/app/AppContainer.tsx). Для публичной страницы заданы [метаданные](../../client/src/shared/config/page-metadata.json) и [канонический адрес](../../client/src/shared/config/canonical-pages.json).

## Этапы и проверка

1. Зафиксировать правки, ожидаемое поведение и затронутые страницы.
2. Уточнить решение, состав файлов и влияние на API, БД, приватность, безопасность и медицинский смысл. На этапе подготовки влияние отсутствует, миграции не планируются.
3. Реализовать согласованные правки. Проверить сборку и lint клиента, страницу `/articles` и переходы из неё. При изменении метаданных или маршрутов проверить сгенерированный HTML.

## Предлагаемая автоматизация каталога

Использовать `analysisType` для разделов и `analysis_type_point` для состава. Повторно использовать три существующих типа (ОАК, железо, белковые фракции), добавить шесть остальных текущих разделов и четыре новых. «Общий анализ мочи» сохранить отдельным типом. Сохранить URL девяти опубликованных страниц.

В серверной модели уже есть `BelongsToMany`. До миграции проверить ограничения уникальности на пару `typeId`, `pointId` и поведение формы при выборе пересекающихся групп. Состав привязок подготовить по отчёту сверки и согласованному распределению.

Включить все 13 групп в групповой выбор формы. В статьях использовать названия «Щитовидная железа» (с АТТГ и АТПО) и «Другие гормоны» (с пролактином). Проверить единый выбор по ID и счётчики для показателя в нескольких группах; пустые группы в форме скрывать. Для статической генерации страниц статей предложен снимок справочника из API на этапе сборки, чтобы сохранить предварительно отрисованный HTML, canonical и sitemap.

### Алиасы и страницы показателей

Предложено добавить `urlAlias` в `analysisType` и `analysisPoint`. Алиасы задаются при создании записи, уникальны в пределах своей таблицы и при переименовании сохраняются. Для существующих разделов перенести опубликованные алиасы без изменения URL. Для показателя предложен один канонический адрес `/pokazateli/<urlAlias>/` со ссылками из всех его групп. Страницы показателей входят в задачу 0047.


Добавить в `analysisPoint` поля `pointDescriptionRu` и `pointDescriptionEn`. Миграция первоначально копирует в них соответственно `pointHintRu` и `pointHintEn`. Страница показателя выводит название и описание для языка сайта. Сейчас публичный интерфейс поддерживает только русский.

На странице раздела вывести название показателя и `pointHintRu`. Вся карточка ведёт на страницу показателя. Удалить вводный текст «Описания приведены из справочника сервиса. Информация не является диагнозом.».

Проверить действующий `pointHintRu` ретикулоцитов перед переносом. На текущей странице есть отдельная поправка к старому справочному тексту. Если ошибка сохранилась в БД, сверить формулировку с источником перед публикацией и отразить решение в документации задачи.

### Источник данных и удаление статических справочников

База данных — источник списка разделов, состава групп, алиасов, названий и описаний. Удалить из клиентского кода `analysis-groups.json`, `analysis-reference-data.json` и ручную карту `groupPointIds`. Обновить ссылки из других частей приложения, сборку и SEO-проверки, которые используют эти списки. При предварительной отрисовке собирать HTML и sitemap на основе данных из БД. Сохранить публичные URL девяти существующих разделов.

Сверка перед миграцией: все 66 общих ID имеют посимвольно одинаковые русские тексты. ГГТП с устаревшим ID 35 представлен в БД действующим ID 62 с тем же описанием. У 29 из 100 показателей нет русского описания. Проверка ретикулоцитов подтвердила, что ошибочный текст всё ещё хранится в `pointHintRu`; исправить исходное справочное описание после сверки с источником и затем перенести его в новое поле. При отсутствии текста выводить карточку или страницу с названием.

### Каталог на главной

Перевести блок «Список расшифровываемых анализов» на тот же каталог БД, что и статьи. В раскрытии каждого типа показывать ссылки на страницы его показателей. Оставить одновременное раскрытие одного типа и закрывать открытый список при клике снаружи.
