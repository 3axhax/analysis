# Сохранение исходных показателей независимо от нормативов

Пользователь требует не блокировать сохранение из-за норматива и не отбрасывать распознанные строки. До изменений создан/проверен backup вне tasks. Существующие изменения сохранить. Индивидуальные значения/ссылки не включать в задачи.

Решение: save выполняет только техническую валидацию point/unit/value, сохраняет ВСЕ исходные строки атомарно. Поиск диапазонов и преобразование выполняются при GET. Новые строки хранят точные sourceValue/sourceUnitId/sourceUnitText; calculation/rule/reference fields остаются null до чтения и не переписываются GET. Старые нормализованные снимки продолжают читаться по сохранённым правилам. Отсутствующий/конфликтующий норматив даёт null status/bounds с явным предупреждением, строка остаётся в результате и не участвует в описаниях.

Требуемая схема: без новых столбцов изменить только CHECK normalized_source_fields, добавив строгое состояние source-only (sourceValue/sourceUnitId заполнены, sourceUnitId=unitId, остальные calculation/provenance/reference null). Существующие legacy/normalized ветки сохранить. До отдельного явного подтверждения пользователя миграцию не выполнять, новый save не активировать на рабочей схеме. Запрос точного разрешения отправлен. Ни backfill, ни normative CRUD не нужны. Down отказывает при наличии source-only записей, чтобы не терять данные.

После разрешения: up/repeat/down на private копии, constraints/row counts/checksums, API mixed-result synthetic test с отсутствующим нормативом; применение локально после свежего backup, обновление backend и проверка обычного API без отправки пользовательской формы. Прогнать unit tests/build/lint/client tests и Nest corpus. Встроенный браузер использовать для проверки готовой UI-индикации только на синтетических данных, пользовательскую форму не очищать/не отправлять. Не создавать фиксации корпуса.

Ограничение области: неизвестный point/unit ID и нечисловое значение — явная техническая ошибка запроса, а не молчаливое исключение строки; запрос атомарен. Текущие лимиты и явная обработка дубликатов сохраняются. Проверки наличия/корректности норматива или возможности конверсии в save полностью убрать.
