# Интеграция миграций в существующий startup

Уточнение проверки: создана третья disposable копия старой БД для двух одновременных первых запусков. Актуальная и первая старая копии проверяют именно полный AppModule init (без override MigrationsService); третья проверяет гонку применения, не только no-op уже обновлённой БД. Рабочие данные не используются как тестовые INSERT/DDL fixtures.

Запрос пользователя: перенести0002/0003/0006 в текущий MigrationsService.onModuleInit, а не требовать отдельного psql. Backup локальной БД создан/проверен до изменений. Схему/сиды и прежние маркеры не менять; на локальной БД все три изменения уже применены, запуск обязан быть no-op. Рабочее дерево изначально чистое, main.

Решение: Nest providers по существующему образцу (единицы и результаты), последовательные вызовы0002→0003→0006 после старых миграций. SQL выполняется через Sequelize; проверка старого marker, транзакция и тот же advisory lock защищают повтор и параллельные старты. Marker записывать в той же транзакции после DDL/seed. При ошибке откатить и не продолжать startup; не выводить SQL/данные/credentials в ошибках. Прежние markers совместимы с ручным применением.

SQL payload перенести в компилируемые TypeScript константы без psql-команд; убрать дублирующие ручные up scripts. Down/verify остаются только для явно согласованного обслуживания, не автостарта. Обновить AGENTS.md и актуальные инструкции задач0002/0003/0006. Не менять существующие unrelated legacy migrations или нормативы/результаты.

Проверки: mock tests no-op/applied/rollback/порядок; две private копии (актуальный backup и предыдущий backup до0002, без удаления современных source-only результатов); first startup/repeat/concurrent startups на старой копии, no-op на актуальной, сравнение catalog/schema и контрольных сумм старых результатов/нормативов. Удаление только созданных disposable копий после проверок, backups сохранить. Рабочую БД не откатывать и не удалять markers. Восстановление backup/новые migrations на копии — только часть прямо запрошенной проверки доставки; локальный startup должен ничего не менять.

Проверить build/runtime packaging: SQL должен поставляться в dist без чтения server/scripts. Если scripts расширили inferred rootDir и ломают штатный dist/main.js, ограничить build src, не включая тестовые CLI. Проверить backend tests/build/lint и обычный health. Не коммитить/пушить без нового запроса пользователя.
