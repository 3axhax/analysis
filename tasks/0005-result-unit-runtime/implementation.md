# Исправление рабочего пути выдачи единиц

До изменения обычный HTTP API выдавал старую запись в source unit с неприведёнными границами target unit и без calculation. На диске новый readResult уже содержал корректную нормализацию legacy-записей. После контролируемого restart dev backend тот же read-only HTTP запрос стал возвращать отдельные source/calculation, коэффициент, согласованные единицы границ и статус. Новая правка формулы не требовалась: потребовалось актуализировать обслуживающий процесс. Точная причина, почему прежний watcher не обеспечил актуальный runtime, не установлена; нельзя полагаться на наличие сборки/health200 вместо проверки реального API.

Backup создан/проверен заранее. Все startup migrations проверены read-only: markers присутствовали, новых DDL не требовалось. Рабочая БД не восстанавливалась и не корректировалась. Контрольные суммы и количества всех20публичных таблиц до/после обновления и проверок совпали; исходные результаты/нормативы не менялись. Новых клинических результатов не создавалось.

Добавлен analysisResult.read.spec.ts с двумя синтетическими regression cases: legacy g/dl→g/l возвращает исходное значение и обратные границы, отдельное расчётное значение и один статус для описаний; неверный интервал даёт null/предупреждение, а не смешанные единицы. Исходный объект остаётся неизменным, DAO-запись для GET не требуется. verify-unit-normalization.ts теперь проверяет legacy-запись именно в конвертируемой, а не уже расчётной unit. На восстановленной private копии API save/get, historical rules, atomicity, k=1 и новый legacy case прошли. Временная копия удалена; backup сохранён вне tasks.

Backend166tests/18suites, build и read-only ESLint затронутых файлов успешны. Corpus18/18,288/288 пар,281/281 ненулевых units,288/288 triples, missing/extra/wrong=0, unscored=0. Входы testData/Python/gold и алгоритм парсинга не менялись, новых промежуточных фиксаций нет. Обычный HTTP endpoint проверен повторно после финальной сборки: расчёт=source×coefficient, displayed bounds×coefficient=reference bounds, status соответствует расчёту. В диагностике использованы реальные enum-коды -1/0/1, не текстовые LOW/NORMAL/HIGH. Результаты проверок выводились только boolean, без сохранения индивидуальных данных/resultId.

В AGENTS.md добавлено правило проверки реального HTTP runtime после изменения save/get; отдельный тестовый App и build не подтверждают поставку. UI по прежнему согласованному контракту показывает source units, границы в тех же units и расчётное значение в подсказке. Для уже открытой страницы требуется повторная загрузка, чтобы заменить ранее полученный ответ в Redux. Ручная браузерная проверка не выполнялась. Коммит/push не выполнялись.

Откат: regression/docs изменения обратимы обычным точечным diff; schema/data migrations не было. Не откатывать runtime на заведомо неверную выдачу единиц и не переписывать исторические медицинские значения ради старого формата.
