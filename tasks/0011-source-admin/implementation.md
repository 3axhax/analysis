# Частичная реализация: отсутствующие границы

Общие нормативы в админке читаются и заменяются только при sourceId=null. Отсутствующая нижняя или верхняя граница передаётся как null и не создаёт запись; ноль сохраняется как числовая граница. При чтении и повторном сохранении сохраняется lowInclusive, а группировка строк не объединяет разные значения этого флага. Ввод нечисловой границы отвергается. Для новых строк оба поля пустые. Схема и миграции не менялись; откат — вернуть изменения кода.

Профильные тесты backend (3), сборки backend/client и client lint прошли; форма добавления проверена без сохранения данных. Проверки API с записью и медицинская проверка не выполнялись. Управление нормативами источников, безопасное редактирование общего справочника единиц при наличии нормативов источников и остальная задача 0011 не реализованы. Существующий CRUD связанных справочников неатомарен.

## Серверная основа выбора источника

Добавлены ADMIN endpoints `GET /admin/medical-sources` и `GET /admin/medical-sources/:sourceId/points`. Возвращаются дерево и признаки собственного норматива, возможности наследования и существующей связи; наличие связи учитывается даже если общий норматив впоследствии отсутствует. Доступность точки не изменяет данных. Вычисление документов группы учитывает вложенность, для записи документом считается конечный некорневой узел. Тесты: дерево/разделение параметров и anonymous/неверный token/USER/ADMIN; анонимный запрос к запущенному API вернул 403. Подключение к формам и изоляция источникового CRUD ещё не выполнены.

## Реализация администрирования

На страницах параметров и описаний выбранный по умолчанию контекст «Без источников» использует общие данные; корневая группа показывает записи её документов. При смене группы состояние фильтра, страницы и формы сбрасывается, устаревшие ответы не восстанавливают прежний список. Для нормативов группы создаётся отдельная запись параметр/документ; форма редактирует существующий общий параметр и его разрешённые единицы, возраст, пол и границы. Отсутствие границы, ноль и lowInclusive сохраняются. В форме описания документ обязателен, условия независимо переключаются между собственными и общими нормативами. Сохранение наследуемого условия добавляет связь, удаление условия или описания её не удаляет. Если у документа одновременно есть собственный норматив и связь наследования, форма отображает оба факта; при расчёте сохраняется существующий приоритет собственных нормативов.

Все новые маршруты находятся под `/admin/medical-sources` и защищены ADMIN: список дерева и справочников, списки группы, доступные параметры документа, сохранение/удаление нормативов и описаний. Мутации документов явно требуют sourceId, а общие CRUD endpoints требуют явно передать null. Транзакции источниковых операций проверяют принадлежность документа группе, допустимые параметры/единицы, дубли и границы; изменение и удаление ограничены указанным документом. Перенос норматива в другой документ предупреждает о возможном влиянии на связанные описания. Существующие общие операции не являются полностью транзакционными; общие единицы, используемые источниками, сохраняются. Удаление общего параметра с зависимостями блокируется.

Схема и миграции не менялись. Тесты backend: 30 наборов, 225 тестов; client: 4 профильных теста, lint; сборки backend/client прошли. Проверены интерфейс, существующие данные источников и отрицательная отправка пустой формы через HTTP. Тесты записи используют mocks, а не реальную БД; сквозная проверка с сохранением синтетических данных в локальную БД остаётся непроведённой. При сборке клиента остались существующие предупреждения CSS и размера bundle. Доставка требует одновременного обновления client и server: общий admin API теперь требует явного sourceId=null.

Интерфейсы источников используют общие компоненты таблицы, модальных окон, селектов и переключателей админки; для них модальное окно располагается над навигацией и ограничено шириной экрана. Таблицы и формы проверены в браузере без сохранения данных.

Нормативы общих данных и источников отображаются общей таблицей с колонками возраста, пола и диапазона. Одинаковые диапазоны обоих полов объединяются только при совпадении возраста, единицы и включённости порога. Односторонние границы и ноль остаются видимыми; при включённости нижнего порога явно выводится строгий знак. Покрыто двумя тестами отображения и проверено в браузере.

Общий каркас страниц владеет выбором источника, заголовком и кнопками добавления; смена группы сбрасывает форму. Обе ветви используют единые Table/TableActions, вывод нормативов и условий, а строка редактирования условия дополнительно принимает настройки источника. Формы и фильтры для общего справочника и документа остаются раздельными из-за разных контрактов данных. Клиентские тесты покрывают открытие форм и переключение контекста; просмотр через браузер выполнен без сохранения.

2026-11-07: по дополнительному замечанию фильтры также объединены: параметры фильтруются по обозначению и переводам RU/EN, описания — по параметру в обоих контекстах. Данные группы фильтруются на клиенте, общий справочник — прежним серверным запросом. При смене группы фильтр сбрасывается; при переходе к описаниям список параметров загружается полностью после постраничного списка администратора. Формы редактирования остаются отдельными из-за разных контрактов данных.
