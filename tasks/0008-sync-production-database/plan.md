# Актуализация локальной БД с рабочего сервера

Цель: обновить локальную БД данными production по запросу пользователя. Подключение по SSH разрешено, параметры читаются из игнорируемого файла без вывода секретов.

Read-only аудит: SSH работает; production PostgreSQL 18, набор public таблиц и migrations markers соответствует локальной обновлённой схеме. Локальный backup создан в sqlDump и проверен pg_restore --list. Рабочая копия содержит документы предыдущей задачи; они сохраняются.

Предлагаемый вариант: полная копия production, включая справочники, нормативы, результаты, пользователей и sessions. Это заменит локальные данные и перенесёт чувствительные данные. До экспорта/import требуется отдельное подтверждение пользователя по AGENTS.md и tasks/README.md. При выборе только справочников требуется отдельный план согласования IDs/FK и сохранённых provenance.

Этапы после подтверждения:
1. Получить custom-format dump по SSH напрямую в игнорируемый sqlDump с закрытыми правами; не выводить содержимое.
2. Проверить архив, восстановить в отдельную локальную staging DB без подключения приложения; production не менять.
3. Read-only проверить constraints, migrations и counts. Не исправлять исторические аномалии автоматически.
4. Остановить локальный backend, повторно сохранить локальное состояние при необходимости, переключить имя БД на проверенную копию, сохранив прежнюю БД для отката.
5. Запустить backend, проверить health и публичные справочники, убедиться в отсутствии неожиданных startup migrations. Не создавать медицинские результаты для smoke test.
6. При сбое вернуть прежнюю БД. Факт переноса и результаты проверок записать обезличенно, без tokens/IDs/медицинских данных.

API/код/нормативная логика не меняются. Production используется только для чтения и pg_dump; локальные сервисы не подключаются напрямую к production. Дампы и секреты не попадают в Git.
