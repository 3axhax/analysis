# Итог

Локальная рабочая БД полностью заменена проверенной копией production после отдельного подтверждения пользователя. Перенесены все 20 public таблиц, включая справочники, нормативы, результаты, пользователей и sessions. Код, API и медицинская логика не менялись; исторические аномалии не исправлялись.

Custom-format dump передан напрямую через SSH в игнорируемый sqlDump с правами 0600. Секреты, архив, результаты и tokens не выводились. На production выполнялись только чтение и pg_dump; приложение локально подключается только к локальной БД.

Восстановление сначала выполнено в отдельную staging DB с --exit-on-error --no-owner --no-privileges. Counts всех 20 таблиц совпали с production, constraints валидны, ожидающих startup migrations нет. Отдельный backend с staging подтвердил health и справочники HTTP 200.

Перед переключением создан повторный проверенный локальный backup. При остановленном backend прежняя БД переименована в analysis_before_sync_20261019, проверенная staging получила штатное имя. После старта API агрегатная проверка полного содержимого всех 20 таблиц подтвердила отсутствие изменений при запуске. Client, API health, analysisPoint, units, analysisType, ages, gender отвечают 200. Проверочный контейнер удалён.

## Откат

Предыдущая БД сохранена локально как analysis_before_sync_20261019; проверенные backup остаются в sqlDump вне Git. Для отката остановить backend, завершить подключения только к локальным переключаемым БД, сохранить текущую копию под свободным именем и вернуть прежней БД штатное имя из окружения, затем запустить backend и проверить API. Не удалять новые результаты и не выполнять down migrations для такого отката. Выполнение отката потребует отдельного запроса пользователя.

## Ограничения

Это снимок production на момент pg_dump, а не постоянная синхронизация. Содержит реальные данные и sessions, поэтому архивы/БД должны оставаться локальными и не публиковаться. Полный пользовательский сценарий сохранения результата не выполнялся; проверочные записи в рабочей локальной БД не создавались. Backend unit/build не повторялись: код не менялся, они прошли в предыдущей задаче восстановления.
