# Реализация исправления единиц

Миграция 0016 методом runRecordedMigration создаёт единицу pmol/L с aliases, добавляет её к FT3/FT4, изменяет их исходно ошибочно размеченные legacy-границы с umol/L на pmol/L без изменения чисел и добавляет версионированные точечные конверсии umol/L ↔ pmol/L с коэффициентами 1000000 и 0.000001. У АЛТ legacy-границы меняются с % на U/L, связь % с новым вводом удаляется. У мочевины возрастные legacy-границы с ошибочной µmol/L меняются на существующий mmol/L; общие конверсии µmol/L↔mmol/L сохраняются. По sourceId источниковые нормы не переписываются. Проверки exact counts предотвращают применение к неожиданной схеме/данным. Снимки и исходные значения измерений не изменяются.

Операция протестирована во временной локальной копии, которой больше нет. Backend build прошёл, 39 тестов unit/migration успешны, три синтетических сценария save/get выполнены на отдельном временном API с тестовой БД; проверены статусы и конверсии без сохранения новых записей в основной БД. Тестовые базы и контейнер удалены. Миграция применена локально, marker есть; API работает.

MCHC 1_3y и дубли диапазонов ГГТП были отдельно исправлены в локальных данных по явному запросу до этой миграции. Самостоятельные показатели ГГТП id35/id62 не объединены; исторические измерения и связанные условия сохранены. Числовые референсы взяты из методички; внешние медицинские источники подтвердили формат единиц, не индивидуальную применимость диапазонов. Production не изменён.

Откат миграции единиц требует предварительного плана: вернуть старые маркировки означает вернуть заведомо неверные референсы; автоматически удалять новые units/rules при наличии результатов нельзя. Предпочтительна исправляющая миграция после анализа provenance. Дополнительный backup не создавался по прямому указанию пользователя.

## Подготовка 0017
Миграция 0017-method45-reference-correction делает повторяемыми согласованные изменения локальных нормативов MCHC и ГГТП. Жёсткие предусловия исключают применение к неожиданному состоянию; на уже исправленной базе она сохраняет данные. Прежнее состояние production и исправленное состояние локальной базы проверены транзакциями с ROLLBACK. Самостоятельные показатели ГГТП не объединяются. Без переписывания сохранённых результатов/правил и без дополнительных backup по указанию пользователя.
