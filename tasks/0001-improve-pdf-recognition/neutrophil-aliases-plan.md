# Уточнение словаря нейтрофилов и контекст формы

Дата: 2026-10-14. Статус: подтверждено пользователем; выполнено, на проверке.

## Область

Изменить только translationParsing двух существующих analysisPoint: neutrophil-count и neutrophil-percentage. IDs, переводы для UI, разрешённые units, нормативы и результаты не меняются. Python и prepared JSON не меняются. Read-only проверка подтвердила по одной записи каждого имени. Локальный backup создан, читаемость и Git-ignore проверены.

## Предлагаемое изменение словаря

- count: удалить неоднозначные отдельные aliases «нейтрофилы» и «NE»; сохранить «neus#» и «число нейтрофилов»; добавить «NEU#», «NE#», «Количество нейтрофилов», «Нейтрофилы, абс.».
- percentage: сохранить текущие aliases; добавить «NE%», «Процент нейтрофилов», «Нейтрофилы, %».
- Не привязывать «Нейтрофилы (общ.число)» безусловно к процентной форме.

## Matcher

Для нейтрофилов использовать общий корень имени только как кандидат формы, не как указание count. Явные маркеры %, #, абс., процент определяют форму внутри текущей записи, до области референсов/комментариев. Противоречащие маркеры или отсутствие признаков дают неоднозначность. Фразы нейтрофилов перенести из EXTRA_NAMES в каталог; названия RU/EN также не должны обходить запрет общего неоднозначного имени. Остальные показатели пока не менять.

## Доставка и rollback

Версионируемый отдельный transactional data-migration script с проверкой ровно двух записей и ожидаемого старого словаря, dry-run по умолчанию, явный apply; не запускать автоматически при Nest startup. Обновлять только translationParsing, не таблицу migrations вручную. Предусмотреть rollback к сохранённым предыдущим фразам с проверкой текущего состояния. До записи требуется подтверждение пользователя; далее read-only проверка количества строк, совпадения словаря и неизменности остальных полей.

## Приёмка

Синтетические tests: относительное общ.число с %, абсолютное абс./#, голое имя без формы, противоречие маркеров, маркер только в референсе, два показателя в одном документе. Полный corpus-прогон на новом read-only snapshot каталога с прежними inputs и expected; старый snapshot/baseline сохранить, отличия каталога явно обозначить. Build, тесты, read-only lint, diff check. Не заявлять общий прогресс по всему differential без отдельной проверки.
