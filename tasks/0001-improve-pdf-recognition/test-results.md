### Агрегированные наблюдения

- Все 10 запросов завершились HTTP 201 без transport error и timeout.
- Статус `complete` не получен ни для одного файла.
- OCR не запускался: все документы имели пригодный текстовый слой.
- `alias_collisions_detected` присутствовал во всех 10 ответах.
- `conflicting_values_require_review` присутствовал в 7 ответах; в одном случае все кандидаты были отброшены.
- 66 из 72 findings получили `multiple_numeric_candidates`.
- 2 findings не получили однозначную единицу измерения.

### Результат проверки

Критерий приёмки задачи «все файлы из `testData/` успешно и корректно распознаются» не выполнен. Техническая обработка стабильна, но агрегированное покрытие составляет 30,9%, а корректность большинства выбранных чисел требует проверки по локальному expected manifest.

## Предлагаемые корректировки

| Приоритет | Корректировка | Проверяемый результат |
|---|---|---|
| P0 | Создать локальный ignored expected manifest и benchmark runner | Рассчитываются precision/recall и unit accuracy без вывода чувствительных данных |
| P0 | Отделить result-column от reference range, дат и примечаний | Значение не выбирается из референса или служебного числа |
| P0 | Переносить роли колонок на продолжения таблиц и следующие страницы | Таблицы без повторного заголовка распознаются в том же контексте |
| P0 | Дедуплицировать одну физическую строку до проверки конфликтов | Разные extractors не создают ложный конфликт одного результата |
| P0 | Ввести слоистый alias index вместо плоского объединения | Primary/fallback/contextual aliases применяются по явным правилам без роста ложных совпадений |
| P1 | Выдавать alias warning только при фактическом неоднозначном совпадении | Глобальная коллизия словаря не переводит каждый документ в `partial` |
| P1 | Добавить проверяемые варианты записи units | Unit определяется только при однозначном совпадении |
| P1 | Добавить regression fixtures найденных классов ошибок | Провалы воспроизводятся автоматическими тестами |
| P1 | Устранить расхождение dev mapping `8000:8000` и документации | Dev-конфигурация имеет явно зафиксированную безопасную модель доступа |

После корректировок необходимо повторить прогон всех 10 файлов. Критерием приёмки служит сравнение с expected manifest; отношение findings к структурно посчитанным строкам остаётся только предварительной метрикой полноты.

Агрегатный анализ текущего словаря, его покрытия и вариантов модификации зафиксирован в `alias-analysis.md`.

## 3. Сравнение прогонов

| Метрика | Baseline | После изменений |
|---|---:|---:|
| Распознано findings | 119 | 72 |
| Покрытие по структурным строкам | 51,1% | 30,9% |
| Ответы с HTTP 201 | 10/10 | 10/10 |
| Явный `unsupported` / `partial` | Нет | 3 / 7 |
| Явный `complete` | Нет | 0 |
| Полный `pointsList` в ответе | Да, 67 элементов | Нет |

Снижение количества findings после изменений связано с отказом от `first candidate wins` и отбрасыванием конфликтующих кандидатов. Это делает контракт честнее, но не доказывает корректность baseline-значений. Для выбора итоговой реализации нужен expected manifest с проверкой precision/recall и unit accuracy.
