# Общий механизм разновидностей count/percentage

Дата: 2026-10-14. Пользователь утвердил общий подход и применение правок. Словарь БД связывает точный код NE с абсолютными нейтрофилами; общий matcher не содержит значения букв NE или отдельной ветки нейтрофилов для выбора формы. Контекст %/#/абс./процент принадлежит имени/началу результата до референса. Точный alias принимается при отсутствии противоречия. Общее однословное имя paired count/percentage не определяет форму самостоятельно.

Область: универсальный resolver для пар каталога `<base>-count`/`<base>-percentage`; перенос существующей special-case проверки в него, без переименования БД/API. Приоритет специфичных aliases, конфликт aliases/markers, unsupported sibling. Существующий запрет клинических подтипов нейтрофилов и RDW-SD остаётся отдельной семантической защитой, не правилом NE. Python/units/expected не менять.

БД: только translationParsing neutrophil-count — добавить _NE к подтверждённому текущему словарю, остальные поля/записи не менять. Backup проверен. Explicit transactional data migration, dry-run по умолчанию, exact precondition, apply после dry-run; rollback обратной миграцией только при ожидаемом состоянии. Исходное предложение о NE и пользовательское «Примени правки» — подтверждение этой области.

Проверки: synthetic неродственные имена и коды, count/percentage, code-prefix protection, contradictory markers, голое имя, маркер в reference, обе формы/порядок; текущие doc-01/doc-05 диагностически; новый snapshot каталога только с NE, inputs/expected fingerprints неизменны; corpus/tests/build/lint/health. Старые snapshots сохранить. Полный перенос EXTRA_NAMES в БД за пределами задачи; общего произвольного семейного metadata в БД пока нет, парность определяется стабильными именами count/percentage.
