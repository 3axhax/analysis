# Распознавание единиц NestJS

Дата:2026-10-15. По запросу пользователя добавить runtime unit recognition к существующему point/value matcher. Перед работой backup локальной БД создан и проверен. Сохранить все незавершённые изменения формата gold pointId/unitId; БД/Python/gold не менять.

Выделять единицу непосредственно после выбранного результата в той же логической строке, включая соседние ячейки, но не произвольные references/соседние результаты. Нормализовать безопасные RU/EN обозначения, пробелы/Unicode и физически численно эквивалентные масштабы counts без преобразования чисел; g/dl и g/l не смешивать. Сопоставлять только с разрешёнными units найденного point, без назначения единственной unit при отсутствии evidence. Дубли evidence с одинаковыми point/value/unit объединять; конфликт единиц оставлять null с явным warning, не выбирать первое наблюдение. Не допускать смену point/value из-за единиц.

Synthetic tests: разные units одного point, отсутствующая/неподдерживаемая/неразрешённая/неоднозначная unit, reference-only unit, разбиение ячеек, точное scale distinction, conflict and concurrency/regression. Затем tests/build/read-only lint/health и весь prepared corpus с unit/triple метриками, без snapshots и автоматической правки gold. Проверить неизменность входов. Отчёт без payload/медицинских значений. Rollback обратной правкой matcher/helper, без DB restore; units остаются подсказкой пользователю, не диагнозом.
