# Итог

Восстановлен dev backend после обновления Git: установлены lockfile dependencies в существующий node_modules volume, запущен backend в актуальной compose network. Собран и запущен отсутствовавший PDF parser. Client/PostgreSQL сохранены.

После отдельного разрешения пользователя и проверенного backup применены существующие ручные миграции 0002, 0003, 0006. При старте выполнилась штатная parsingOrder. Исторические результаты, исходные поля измерений, нормативы и counts проверены на неизменность до и после старта; непроверенных constraints нет. Нормативы и результаты не исправлялись.

Up/repeat/down/up и synthetic constraints проверены на disposable DB, удалённой после проверки. Штатные down выполняются в обратном порядке и отказывают при наличии использующих новую схему данных; принудительно удалять результаты для отката нельзя. Backup остаётся локально в игнорируемом sqlDump.

Backend build и 185 tests / 19 suites успешны. Python 11 tests и compileall с временным cache prefix успешны. API/client health и публичные справочники отвечают 200, admin endpoint без token — 403. Parser healthy и доступен backend по внутренней сети; опубликованный localhost:8000 с хоста не отвечает из-за internal сети. Рабочий PDF pipeline использует внутренний адрес. Реальные PDF не открывались, POST save в рабочую БД не выполнялся. Полный браузерный сценарий сохранения/разбора не проверялся.

Прикладной код не менялся; в Git добавлены только документы этой задачи. Предупреждения ts-jest и npm deprecations оставлены вне рамок восстановления.
